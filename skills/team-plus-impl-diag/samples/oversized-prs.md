# タスク分解（このリポジトリ向け）

実装に着手する**前に**、作業を PR 単位へ分解する skill。

原則は **1 Task = 1 PR = 1 Revert Unit**。「その PR だけを revert しても壊れないか」を分割の判定基準にする。行数は結果であって基準ではない。

## 実行手順

1. 対象の Issue / 要件を読む
2. 下記「このリポジトリの前提」に照らして分割候補を出す
3. 各 PR について「revert しても壊れないか」を判定する。壊れるなら依存関係として明示する
4. 分割案を出力する

## 出力形式

```markdown
## 分割案（N PR）

### PR 1: <タイトル>
- 変更範囲: <パス>
- 単独 revert: 可 / 不可（不可なら理由と依存先）
- 想定規模: <おおよその行数と、その根拠>
- レビュー観点: <レビュアーに見てほしいところ>

### PR 2: ...

## 依存関係
<!-- 直列でなければならない箇所だけを書く。並行できるものは並行と明示 -->

## 分割しない判断をした箇所
<!-- 分けられそうに見えて分けなかったものと、その理由。ここが後から効く -->
```

**「分割しない判断をした箇所」を必ず書く。** 分けなかった理由が残っていないと、次の人が同じ検討を繰り返す。

## 使うタイミング

**実装着手前**に使う。書き終わってから分割するのは、コストが跳ね上がるうえ大抵は実行されない。Issue に着手する標準ステップに組み込むのが定着の条件。

## 導入後に確認すること

次回の診断で `avg_lines_changed_per_pr` を見る。**併せて `prs_merged / prs_created`（S11）も見ること** — 細かく分けすぎて破棄される PR が増えていないかを確認する。
