# AI 一次レビュー

人間レビュアーが読む前に、**機械的に判定できる指摘を先に片付ける**ための skill。

狙いはレビューの置き換えではなく**分業**。機械的指摘（規約・テスト漏れ・タイポ・定型の抜け）を先に処理し、人間には設計判断・仕様の妥当性・影響範囲の見落としだけを残す。

## 実行手順

1. 対象 PR の差分を取得する
2. 下記「一次レビューの観点」で照合する
3. 指摘を**機械的指摘**と**人間に回すもの**に分類して出力する
4. 人間に回すものには「なぜ機械で判定できないか」を一言添える

## 出力形式

```markdown
## 一次レビュー結果

### 機械的指摘（N 件）
<!-- ファイル:行 と、何がどう規約に反するかを 1 行で。根拠となる規約の参照先も -->

### 人間レビュアーへの申し送り（N 件）
<!-- 判断が必要な論点。AI の結論は書かず「何を判断してほしいか」だけを書く -->

### 確認済み（指摘なし）
<!-- どの観点を見て問題なかったかを列挙。人間が二度見しなくて済むように -->
```

**「確認済み」を必ず出す。** 何を見たか分からないと、人間は結局全部見ることになり負荷が減らない。

## 導入の順序

1. **まず原因を切り分ける。** 診断レポートで該当メンバーの `reviews_created` を見る
   - **件数が多い** → 量の問題。この skill が直接効く
   - **件数が多くない** → 量以外（レビュー対象の難度・稼働の断続・依頼の偏り）。この skill の前に依頼ルーティングを見直す
2. 観点を抽出して上記を埋める
3. レビューフローの前段に配置する（PR オープン時の自動実行にすると定着しやすい）
4. **人間レビューの対象を明示的に狭める。** ここを運用ルールとして合意しないと、一次レビューが増えただけになる

## 導入後に確認すること

次回の診断で `avg_time_to_my_review` を見る。**チーム全体の値も併せて見ること** — 特定個人だけ下がって他の人に移っただけ、という結果になっていないかを確認する。
