# セルフレビュー（チーム固有チェックリスト内蔵）

PR を作る前に自分の変更を点検し、**レビュアーが読み始めるまでの摩擦を減らす**ための skill。

レビュー着手が遅れる原因は「レビュアーが忙しい」だけとは限らない。**何を見ればいいか分からない PR は後回しにされる**。この skill は指摘の先回りと、PR 説明の整備の両方を行う。

## 実行手順

1. 変更差分を取得する（未コミットなら working tree、コミット済みならデフォルトブランチとの差分）
2. 下記チェックリストと照合し、該当する指摘を挙げる
3. 指摘は**根拠となる差分の該当箇所**を添えて出す。指摘が無い項目は黙る
4. PR 説明の草案を出力する

## PR 説明の草案

以下の形式で出力する。**レビュアーが最初の 30 秒で「どこを見ればいいか」を判断できること**が目的。

```markdown
## 何を変えたか
<!-- 1〜2 行。実装の説明ではなく、変わる振る舞い -->

## なぜ
<!-- 背景。Issue があればリンク -->

## 重点的に見てほしいところ
<!-- レビュアーの視線を誘導する。「全体的に」と書かない -->

## 見なくてよいところ
<!-- 自動生成・機械的置換など。差分は大きいが読む必要がない箇所 -->

## 確認したこと
<!-- 動作確認・テストの実行結果 -->
```

## 出力の作法

- 指摘は**多くても 5 件まで**。全部挙げると読まれない
- チェックリストに無い一般論の指摘はしない（それは汎用のレビュー skill の仕事）
- 該当が 1 件も無ければ「チェックリスト上の指摘なし」と明示して終わる

## 導入後に確認すること

次回の診断で `lead_time_pr_to_review` を見る。該当メンバーの値が team avg × 2 を下回れば S2 は解消。**下がらない場合は原因がレビュー依頼側ではなくレビュアー側にある**可能性が高いので、`reviewer-overload` の提案（`samples/reviewer-overload.md`）に切り替える。
